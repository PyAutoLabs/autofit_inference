# hpc

Driving the RAL HPC from the laptop, and getting runs back. Copied from
`autolens_inference/hpc/`, trimmed to CPU jobs: this repo benchmarks searches on toy
likelihoods and has no GPU submits.

## Layout

```
sync                    laptop-side driver (below)
sync.conf.example       template; sync.conf is gitignored
batch_cpu/
  template              the shape every CPU submit is copied from
  submit_<name>         one submit per run (none yet — they arrive with the harness)
  output/   error/      SLURM stdout/stderr (gitignored; .gitkeep tracked)
```

## Partitions

CPU jobs use `--partition=ral` (`--cpus-per-task=8`). **There is no `cpu` partition on
RAL**, and bulk CPU arrays never go on `gpu` (nor `ral,gpu`) — they starve the A100s. Check
with `sinfo` before inventing a partition name.

## Running

On the login node:

```bash
cd /mnt/ral/jnightin/inference/autofit_inference
source activate.sh          # shared venv + PYTHONPATH at PyAutoNerves and PyAutoFit
cd hpc/batch_cpu && sbatch submit_<name>
```

The PyAuto* libraries resolve from the shared source checkouts on `PYTHONPATH` — never
pip-install them into the venv (`HPCPullPyAuto` is the update story). `activate.sh` also
sends every cache under `/mnt/ral/jnightin/.cache`, never `$HOME` or `/tmp`, and inside a
SLURM job sets `set -eE` plus an `ERR` trap so a crashed job is recorded as FAILED rather
than `COMPLETED 0:0`.

## `hpc/sync` — the laptop-side driver

```bash
cp hpc/sync.conf.example hpc/sync.conf   # then edit; sync.conf is gitignored
```

| verb | what it does |
|------|--------------|
| `hpc/sync pull` | Download batch logs, then run outputs and results |
| `hpc/sync logs` | Batch logs only — small and fast, use mid-run |
| `hpc/sync status` | Dry run: what a pull would transfer |
| `hpc/sync submit [--cpu] <name>` | `sbatch` a submit script, from `hpc/batch_cpu/` |
| `hpc/sync jobs` / `sacct` / `cancel <id>` | `squeue` / `sacct` / `scancel` |
| `hpc/sync tail [cpu]` | Stream the newest live `.out` |
| `hpc/sync du` | Remote disk usage |
| `hpc/sync check` | Verify SSH, remote paths, `sbatch`, and the local pull root |

`submit` runs `sbatch` **from `hpc/batch_cpu/`**, because the submit scripts' `#SBATCH -o`
/ `-e` paths are relative. A pull lands in **this checkout** (`LOCAL_PULL_ROOT` defaults to
the repo root); `output/` is gitignored and a pulled result row is committed by a human
from here — a job on RAL never commits.

### Scored wave 2 (B5a)

The wave-2 submits and their task tables are **generated**
(`python scripts/misc/tooling/plan_wave2.py --write`; lint runs `--check`):

| submit | array | what |
|---|---|---|
| `submit_wave2_reference_<dataset>` | one task per reference run | per new realisation and backend: 3 Nautilus `n_live=2000` + 3 DynestyStatic `nlive=1000` (blend also: JAX Nautilus seed 1 on realisation 1, NSS `ln 3!`) |
| `submit_wave2_reference_build_<dataset>` | one per (backend, new realisation) | MAP reference, then `build_reference.py` |
| `submit_wave2_scored_<dataset>_<backend>` | one per (cell, realisation, seed block) | the scored runs, each under its frozen `@2` timeout |
| `submit_wave2_probe` | one per probe run | the probe-first cells (Zeus JAX, NSS), realisation 1, seeds 0–4 |
| `submit_wave2_remainder` | one per (cell, realisation, seed block) | B5b: the probe-first cells' other 980 runs, each under its probe-derived `@2` timeout (`results/calibration/gaussian_x3_wave2_probe.json`, from `write_probe_timeouts.py`) |

Order: on the login node `git fetch && git checkout <branch>` and build the private pin
(`.pyauto_pin/PyAutoFit` at `_wave2.PYAUTOFIT_PIN`, `.pyauto_pin/PyAutoNerves` at
`PYAUTONERVES_PIN`, plus `.pyauto_pin/site` with the wheels of `_wave2.PIN_SITE_PACKAGES`
unpacked into it — the shared venv lacks `zeus`; never `HPCPullPyAuto`, never modify the
shared venv); submit the two reference arrays and the probe;
then each build with `--dependency=afterany:<its reference array>`; then the four scored
arrays with `--dependency=afterany:<both builds>` (`hpc/sync submit --cpu <name>
--dependency=…` passes options to `sbatch`). Every submit runs on `--partition=ral` with
2 CPUs per task, excludes the four 252-CPU nodes (whole-node jobs of other campaigns fit
only there) and throttles each scored array to `%60` (240 tasks, 480 CPUs in all).

After the probe: pull its rows, run `write_probe_timeouts.py` and `plan_wave2.py
--write`, and submit `submit_wave2_remainder` (B5b: job 409930). The scored arrays and the
probe keep the menu as B5a submitted it, so their committed files never move.
Pulling ~12 000 small rows by rsync over the RAL NFS ran at ~0.16 files/s, and B5b
pulled `results/` as a parallel per-directory `tar` on the login node instead.

### The `correlated_nd` pilot (B5c)

`submit_correlated_nd_pilot` and `batch_cpu/correlated_nd/pilot.tsv` are generated by
`python scripts/misc/tooling/plan_correlated_nd.py --write` (lint runs `--check`): one array
task per run (930: every non-deferred cell × seeds 0–9 × realisation 1), each run under the
pilot's 4 h operational cap, `--partition=ral` only, the same exclusions and private pin as
wave 2, 2 CPUs and 8 GB per task, throttled to `%100`. It runs from the private copy
`/mnt/ral/jnightin/inference/autofit_inference_b5c` (the delivered files plus its own copy
of `.pyauto_pin/`), never the shared clone, which another session switched branches on
mid-submission (B5c: RAL 409957 failed at import and was cancelled). Protocol
`wiki/project/protocol_correlated_nd.md` §7.

### There is no `push`

The RAL copy is a **git clone** at `/mnt/ral/jnightin/inference/autofit_inference`. Code goes to RAL
with git on the login node (`git status`, then `git pull`); `hpc/sync push` prints that
procedure and exits non-zero.
